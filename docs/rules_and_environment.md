# 比赛规则与评测环境

本文给出公开发布包中的参赛边界。比赛鼓励开放的算法探索，但提交物必须能够被评测器自动、可复现地运行。

## 1. 方法开放性

参赛者可以自由选择编译方法，包括但不限于：

- 手写启发式、搜索、图算法、动态规划或局部优化。
- 机器学习、强化学习、自动调参或生成式方法。
- 使用公开资料、公开开源库和公开论文中的方法。
- 使用 LLM 辅助编写、解释或重构代码。
- 使用 CPU、GPU、Apple Silicon、并行计算或向量化加速。

不强制使用仓库内 baseline，也不限制必须沿用 Cirq RouteCQC。

## 2. 禁止行为

提交不得依赖下面这些方式得分：

- 读取、推断或硬编码 hidden test 的答案、样本名、内部路径或非公开数据。
- 只为公开样本准备固定输出 bitstring，而不实现输入线路的等价编译。
- 修改评测器、绕过结构校验、利用运行时漏洞或依赖评测机器上的非公开文件。
- 在最终评测中要求人工交互、人工登录或手动选择文件。
- 在最终评测中依赖不可复现的私有在线服务、私有 API key 或参赛者个人账号。

如果使用外部公开资源训练或生成策略，提交说明中应写明资源来源和运行方式。

## 3. 评测硬件量级

正式评测会使用单机环境运行提交命令，目标硬件量级大致为：

- 单张 NVIDIA RTX 5090 级别 GPU 的工作站；或
- 单台 Apple M4 Mac mini，约 16GB 内存；或
- 主办方认为性能相近的单机环境。

主办方会尽量保持评测环境一致，但保留根据实际排期、驱动和可用机器调整等价环境的空间。参赛程序应能在普通单机开发环境中运行，不应假设多机集群、超大内存、专用商用服务或固定 GPU 型号必然可用。

## 4. 运行约束

公开评测 CLI 默认对每个样本设置 `--timeout-sec 30`。正式评测的 timeout、shot 数、随机种子和样本数量可能根据比赛规模调整，并会在正式评测说明中公布。

建议参赛者满足下面的工程约束：

- 编译器命令必须接受 `--circuit`、`--backend` 和 `--out`。
- 命令应能在干净工作目录中运行，不依赖当前目录下的 `benchmark.json`。
- 每个样本应在分钟级以内完成编译；长时间搜索应设置自己的停止条件。
- 输出文件大小应保持在评测器限制内；当前公开评测限制为 2 MB。
- 代码应固定随机种子或在说明中解释随机性来源。

## 5. Public 与 Hidden Test

公开数据用于本地调试、格式验证和 baseline 对比。Hidden test 会遵循同一输入输出接口、后端 schema、提交格式和评分公式，但会使用未公开的线路样本、后端快照或随机种子组合。

公开分数不保证等于最终 hidden 分数。一个健壮提交应优化一般的 layout、routing 和 noise-aware decomposition，而不是只针对公开文件名或公开答案做特化。

## 6. 同分处理

主排名按最终分数从高到低排序：

```text
Final Score = 0.75 * TrackA + 0.25 * TrackB
```

如最终分数相同，主办方可参考下面的信息作并列说明或附加排序：

- hidden Track A 分数；
- hidden Track B 分数；
- 平均编译时间；
- 代码可复现性和提交说明完整性。

具体 tie-breaker 以赛前公布的正式规则为准。
